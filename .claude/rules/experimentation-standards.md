# Experimentation Standards

## Hypothesis Quality (5 Required Elements)

Every hypothesis MUST contain all five:

1. **Observation** — data or research that prompted this idea
2. **Change** — the specific modification being proposed
3. **Expected outcome** — directional prediction (increase/decrease by X%)
4. **Audience** — who this affects (all users, mobile, NL market, etc.)
5. **Metric** — how success will be measured

**Template:** "Because [observation/data], we believe that [change] will cause [expected outcome] for [audience], which we will measure by [metric]."

**Reject any hypothesis that:**
- Has no data backing (just "we think")
- Doesn't specify a measurable outcome
- Doesn't define the target audience
- Doesn't name a specific metric

## PXL Scoring

| Field | Range | Criteria |
|-------|-------|----------|
| Above fold? | 0-1 | Change is visible without scrolling |
| Noticeable in 5 sec? | 0-1 | Users notice the change within 5 seconds |
| Adding/removing element? | 0-1 | Test adds or removes (not just modifies) |
| Increases motivation? | 0-1 | Appeals to user motivation/desire |
| High traffic page? | 0-1 | Page receives significant traffic |
| Research backing | 0-6 | 1 point per source: user testing, analytics data, qualitative research, heatmaps, survey, A/B test |
| Ease of implementation | 0-3 | <4h=3, <8h=2, <2 days=1, >2 days=0 |

**Max PXL Score:** 12. Higher = prioritise first.

## AARRR Categories

| Category | Meaning | Example metrics |
|----------|---------|----------------|
| Acquisition | Getting users to the site | Traffic, CTR, bounce rate |
| Activation | First valuable action | Add-to-cart, signup, first purchase |
| Revenue | Generating money | Conversion rate, AOV, revenue per user |
| Retention | Bringing users back | Repeat purchase rate, LTV, churn |
| Referral | Users bringing others | NPS, referral rate, social shares |

## Status Workflow

```
Draft → Backlog → To Do → In Progress → Running → Done → Parked
```

- **Forward only** (except Parked, which can come from any status)
- Status change triggers: Draft→Backlog (after PXL scoring), Backlog→To Do (sprint assignment), To Do→In Progress (build starts), In Progress→Running (launched), Running→Done (results analysed), Any→Parked (deprioritised)

## Naming Convention

Experiment names follow: `EXP-{ID} | {Short Name}`

- Auto-generated by the `Exp name` formula field
- `Short Name` should be descriptive but concise (3-8 words)
- Good: "Mobile sticky add-to-cart button"
- Bad: "Test 1" or "New experiment"

## Result + Action Taken

| Result | Action Taken | Meaning |
|--------|-------------|---------|
| Win | Implement | Statistically significant positive result → ship it |
| Win | Iterate | Positive but room for improvement → run follow-up |
| Learn (loss) | Abandon | Statistically significant negative result → stop |
| Learn (loss) | Iterate | Negative but insight gained → try different approach |
| Inconclusive | Iterate | Not enough data → retest with changes |
| Inconclusive | No Action | Not enough data + low priority → move on |
| Error | No Action | Technical failure → fix and retest |
